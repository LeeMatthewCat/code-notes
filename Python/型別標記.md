# 概念與原理

## 什麼是型別標記 (Type Hints)？

Python 是一門**動態型別語言 (Dynamically Typed Language)**。在執行期，變數的型別由所賦予的物件決定，變數名稱本身不綁定型別。

自 Python 3.5 (PEP 484) 起，Python 引入了**漸進式型別系統 (Gradual Typing)**。透過在變數、函式參數與回傳值後方附加「型別標註 (Type Annotations)」，讓開發者能夠在代碼中明確宣告資料規格。

> **[核心天條]：型別標記在執行期預設不具強制力！**  
> Python 直譯器在執行程式時，**完全不會主動驗證**型別標記是否正確。若傳入與註記不符的型別，程式依然會照常執行（除非程式碼邏輯本身引發例外）。  
> 型別標記的主要價值在於：
> 1. **IDE 智慧開發體驗**：提供毫秒級的自動補全、參數提示與即時拼錯紅線警告。
> 2. **靜態程式碼分析 (Static Analysis)**：由 `mypy`、`pyright` 等工具在執行前進行自動化掃描，攔截潛在邏輯缺陷。
> 3. **現代資料驗證框架底層核心**：`Pydantic`、`FastAPI`、`FastMCP` 依賴型別註記在執行期進行資料校驗與 JSON Schema 轉換。

> **[生動比喻]**：  
> - **無型別標註的 Python**：像「純黑色不透明收納箱」，在打開拿出來用之前，你無法確定箱子裡裝的是工具、水果還是玻璃杯。  
> - **標註型別的 Python**：像「透明壓克力收納箱並貼上出廠規格條碼」，箱外清楚標示規格尺寸。倉庫巡檢員 (Mypy) 拿掃描槍一掃就能抓出誤裝，但收納箱本身依然維持輕巧靈活！

# 現代語法升級與版本演進對照表

Python 經歷了多次型別系統重大迭代：
- **Python 3.5 - 3.8**：必須自 `typing` 模組引入首字大寫的特殊泛型容器（如 `List`、`Dict`、`Union`、`Optional`）。
- **Python 3.9 (PEP 585)**：內建原生容器支援直接作為泛型使用（如 `list[int]`、`dict[str, Any]`、`type[User]`）。
- **Python 3.10 (PEP 604)**：引入垂直線管道符號 `|`，取代傳統的 `Union` 與 `Optional`。

| 功能操作 | 舊式語法 (已棄用 / 3.10 前) | 現代標準語法 (推薦 / 3.10+) | 核心差異與說明 |
| :--- | :--- | :--- | :--- |
| **清單列表容器** | `typing.List[int]` | `list[int]` | 無需額外 `import`，原生內建 `list` 直接支援下標泛型 (PEP 585) |
| **鍵值字典容器** | `typing.Dict[str, int]` | `dict[str, int]` | 原生內建 `dict` 直接支援下標泛型 (PEP 585) |
| **固定與不定長元組** | `typing.Tuple[int, str]` | `tuple[int, str]` | 原生內建 `tuple` 直接支援下標泛型 (PEP 585) |
| **集合容器** | `typing.Set[str]` | `set[str]` | 原生內建 `set` 直接支援下標泛型 (PEP 585) |
| **聯合型別 (多選一)** | `typing.Union[int, str]` | `int \| str` | 使用管道符號 `\|` 取代冗長的 `Union` (PEP 604) |
| **可空型別 (可能為 None)** | `typing.Optional[str]` | `str \| None` | 語意更直觀清晰，消除 `Optional` 容易被誤解為「預設參數可選」的歧義 |
| **類別物件型別** | `typing.Type[User]` | `type[User]` | 原生內建 `type` 直接支援下標泛型 (PEP 585) |
| **可呼叫物件** | `typing.Callable[[int], str]` | `collections.abc.Callable[[int], str]` | 推薦從 `collections.abc` 引入，統一標準抽象集合介面 |
| **可迭代與迭代器** | `typing.Iterable[int]` | `collections.abc.Iterable[int]` | 推薦從 `collections.abc` 引入抽象協定 |
| **自引用與前向參照** | `"Node"` (字串引號包覆) | `Node` (需宣告延遲解析) | 檔案開頭加入 `from __future__ import annotations` (PEP 563) |

# 1. 容器與基礎資料型別標註 (Collections & Basic Types)

在 Python 中，所有標準容器均可指定其內部容納之元素型別。

##### list 與 List 列表型別

- **使用時機**：需要標註一個長度可變、內部元素型別一致的串列時使用。
- **語法**：
  - 現代語法 (3.9+)：`list[元素型別]`
  - 舊式語法 (3.8 前)：`typing.List[元素型別]`
- **參數說明**：
  - `元素型別`：列表中所存放物件之型別。
- **回傳值**：
  - 型別別名物件 (GenericAlias)。

```python
# 1. 現代標準寫法 (Python 3.9+)
names: list[str] = ["Alice", "Bob"]
numbers: list[int] = [1, 2, 3]

# 2. 舊式寫法 (Python 3.8 以前，需 import List)
from typing import List
old_scores: List[float] = [95.5, 88.0]
```

---

##### dict 與 Dict 字典型別

- **使用時機**：標註鍵值對結構的映射表時使用，需同時指定 Key 與 Value 之型別。
- **語法**：
  - 現代語法 (3.9+)：`dict[鍵型別, 值型別]`
  - 舊式語法 (3.8 前)：`typing.Dict[鍵型別, 值型別]`
- **參數說明**：
  - `鍵型別`：字典 Key 之型別（必須為可雜湊 Hashable 型別，如 `str`, `int`）。
  - `值型別`：字典 Value 之型別。
- **回傳值**：
  - 型別別名物件。

```python
# 1. 現代標準寫法：Key 為 str，Value 為 int
user_ages: dict[str, int] = {"Alice": 25, "Bob": 30}

# 2. 巢狀字典標註
user_profiles: dict[str, dict[str, str]] = {
    "admin": {"email": "admin@example.com", "role": "root"}
}
```

---

##### tuple 與 Tuple 元組型別

- **使用時機**：元組標記具備兩種截然不同的模式，使用時必須特別注意：
  1. **固定長度異質元組 (Fixed-length Heterogeneous Tuple)**：元組中每個位置的型別獨立宣告。
  2. **不定長度同質元組 (Arbitrary-length Homogeneous Tuple)**：長度不限，所有元素皆為同一型別，**必須加上省略號 `, ...`**。
- **語法**：
  - 固定長度：`tuple[型別1, 型別2, ...]`
  - 不定長度：`tuple[型別, ...]`
- **參數說明**：
  - 括號內逗號分隔之型別序列；若最後一個參數為 `...` 則代表任意長度。
- **回傳值**：
  - 型別別名物件。

```python
# 1. 固定長度：長度嚴格為 2，第 0 項為 int，第 1 項為 str
coordinate: tuple[int, int] = (10, 20)
user_record: tuple[int, str, bool] = (1, "Matthew", True)

# 2. 不定長度同質元組：長度任意，但內部所有元素必須為 int (務必加上 ...)
numbers_stream: tuple[int, ...] = (1, 2, 3, 4, 5)
```

---

##### set 與 Set 集合型別

- **使用時機**：標註元素不重複之無序集合。
- **語法**：
  - 現代語法 (3.9+)：`set[元素型別]`
  - 舊式語法 (3.8 前)：`typing.Set[元素型別]`
- **參數說明**：
  - `元素型別`：集合內部元素之型別（必須為可雜湊型別）。
- **回傳值**：
  - 型別別名物件。

```python
unique_tags: set[str] = {"python", "git", "backend"}
```

# 2. 聯合、可空與函數型別 (Unions, Optionals & Callables)

##### Union 與 管道運算子 聯合型別

- **使用時機**：當變數、參數或回傳值允許接受兩種或多種不同型別其中之一時使用。
- **語法**：
  - 現代語法 (3.10+)：`型別1 | 型別2 | ...`
  - 舊式語法 (3.9 前)：`typing.Union[型別1, 型別2, ...]`
- **參數說明**：
  - 候選型別序列。
- **回傳值**：
  - 聯合型別物件 (`types.UnionType` 或 `typing.Union`)。

```python
# 1. 現代標準寫法 (Python 3.10+ 原生管道符號)
def parse_id(raw: int | str) -> str:
    return str(raw)

# 2. 舊式寫法 (Python 3.9 以前)
from typing import Union

def old_parse_id(raw: Union[int, str]) -> str:
    return str(raw)
```

---

##### Optional 與 可空標記

- **使用時機**：當變數可能為特定型別，亦可能為空值 (`None`) 時使用。
- **語法**：
  - 現代語法 (3.10+)：`型別 | None`
  - 舊式語法 (3.9 前)：`typing.Optional[型別]`
- **參數說明**：
  - `型別`：非空時的實際型別。
- **回傳值**：
  - 聯合型別物件（`Optional[T]` 本質等價於 `Union[T, None]`）。

> **[小提醒]：Optional 不等於「預設為可選參數」！**  
> 許多初學者常誤以為 `name: Optional[str]` 代表呼叫函式時可以不傳 `name`。  
> 實際上，`Optional[str]` 僅表示「允許傳入 `None`」；若沒有賦予預設值（例如 `name: str | None = None`），呼叫時依然是必填參數！

```python
# 1. 現代標準寫法 (推薦)：清楚表達「為 str 或為 None」
def find_user(user_id: int) -> str | None:
    if user_id == 1:
        return "Alice"
    return None

# 2. 帶有預設值的非必填參數
def greet(message: str | None = None) -> None:
    if message is not None:
        print(message)
```

---

##### Callable 可呼叫物件型別

- **使用時機**：標註一級函式、類別方法、匿名函式 (Lambda) 或實作了 `__call__` 的物件實體時使用。
- **語法**：
  - `Callable[[參數型別1, 參數型別2, ...], 回傳型別]`
  - 若不限制參數個數與型別，可將參數串列寫為省略號：`Callable[..., 回傳型別]`
- **參數說明**：
  - 第一個引數：包含所有參數型別之列表。
  - 第二個引數：函式之回傳值型別。
- **回傳值**：
  - 可呼叫型別協定物件。

```python
from collections.abc import Callable

# 1. 標註接收兩個 int 並回傳一個 int 的運算函式
def compute(a: int, b: int, operator: Callable[[int, int], int]) -> int:
    return operator(a, b)

# 傳入 lambda 測試
result = compute(10, 5, lambda x, y: x * y)  # 輸出: 50

# 2. 不限制參數規格，僅限定回傳字串
logger_callback: Callable[..., str]
```

# 3. 序列、迭代器與產生器型別 (Iterables & Generators)

##### Iterable 可迭代物件型別

- **使用時機**：當函式只需要使用 `for item in items:` 逐筆讀取資料，不在乎傳入的是 `list`、`tuple`、`set` 還是產生器時，應優先標註為 `Iterable`（遵循依賴最小介面原則）。
- **語法**：`Iterable[元素型別]` (推薦自 `collections.abc` 引入)
- **回傳值**：抽象可迭代型別。

```python
from collections.abc import Iterable

def calculate_sum(numbers: Iterable[int]) -> int:
    total = 0
    for n in numbers:
        total += n
    return total

# list、tuple、set 皆可相容傳入
calculate_sum([1, 2, 3])
calculate_sum((10, 20))
calculate_sum({100, 200})
```

---

##### Iterator 迭代器型別

- **使用時機**：標註具備內部游標狀態、可透過 `next(it)` 持續取出下一筆資料之迭代器實體。
- **語法**：`Iterator[元素型別]` (推薦自 `collections.abc` 引入)
- **回傳值**：抽象迭代器型別。

```python
from collections.abc import Iterator

def stream_tokens() -> Iterator[str]:
    yield "token_1"
    yield "token_2"
```

---

##### Generator 產生器型別

- **使用時機**：當撰寫 Python 產生器函式 (`yield`) 時，需對其資料流向進行最嚴格的三維度標註。
- **語法**：`Generator[Yield型別, Send型別, Return型別]` (推薦自 `collections.abc` 引入)
- **參數說明**：包含三個順序不可調換之引數：

| 參數位置 | 參數名稱 | 核心意義與流向 | 典型填寫值 |
| :--- | :--- | :--- | :--- |
| **第 1 項** | `Yield型別` | 每次執行 `yield x` 向外吐出給呼叫端的資料型別 | 關注的主要產出型別 (如 `int`, `str`) |
| **第 2 項** | `Send型別` | 外部透過 `gen.send(val)` 傳入產生器內部的資料型別 | 若不接收外部傳入，**一律設為 `None`** |
| **第 3 項** | `Return型別` | 產生器結束並拋出 `StopIteration(value)` 時的最終回傳型別 | 若無顯式 `return value`，**一律設為 `None`** |

```python
from collections.abc import Generator

# 定義產出 int，不接收外部輸入 (None)，結束時回傳字串訊號 (str) 的產生器
def countdown(start: int) -> Generator[int, None, str]:
    while start > 0:
        yield start      # Yield型別: int
        start -= 1
    return "火箭發射！"  # Return型別: str

# 調用示範
gen = countdown(3)
print(next(gen))  # 輸出: 3
print(next(gen))  # 輸出: 2
print(next(gen))  # 輸出: 1

try:
    next(gen)
except StopIteration as e:
    final_message = e.value  # 取得 return 的值
    print(final_message)     # 輸出: 火箭發射！
```

# 4. 特殊型別、字面值與元數據 (Special Types & Metadata)

##### Any 任意型別

- **使用時機**：表示該變數可接受任何型別，**靜態型別檢查器遇到 Any 時會完全停用型別校驗**，直接放行。僅用於動態過渡或特殊底層橋接。
- **語法**：`from typing import Any`
- **核心定位**：全域通用逃生門 (Escape Hatch)。

```python
from typing import Any

raw_data: Any = 123
raw_data = "Hello"  # 靜態檢查器完全不報警
```

---

##### Literal 字面值限定型別

- **使用時機**：當變數不僅限定型別，更嚴格限定其**值必須是預先列舉的固定純量常數**（字串、整數、布林值）時使用。常取代簡易 Enum。
- **語法**：`Literal[值1, 值2, ...]` (Python 3.8+ 於 `typing` 引入)
- **參數說明**：允許的具體常數數值清單。

```python
from typing import Literal

# 1. 限定連線模式只能為指定的三種字串
Mode = Literal["read", "write", "append"]

def open_file(path: str, mode: Mode) -> None:
    pass

open_file("log.txt", "read")   # 正確
# open_file("log.txt", "edit") # 靜態型別檢查器會直接標紅線報錯！

# 2. 限定狀態碼只能為特定的整數
StatusCode = Literal[200, 404, 500]
```

##### Annotated 附加元數據型別

- **使用時機**：在 **Python 3.9+** (PEP 593) 引入。當你需要在純型別之上**額外附加宣告性元數據 (Metadata)**，且希望這些元數據能被執行期框架（如 FastAPI、Pydantic）解析，但**完全不干擾 IDE 的純型別推導**時使用。
- **語法**：`Annotated[實質型別, 元數據1, 元數據2, ...]`
- **結構剖析與解構規則**：
  - 第一個參數（索引 `0`）：**底層真實型別**（IDE 與 mypy 只看這一項）。
  - 後續所有參數（切片 `[1:]`）：附加的自訂元數據物件（可以是字串、字典或特定約束物件）。
  - 可透過 `typing.get_args()` 於執行期將其完美解構。

```python
from typing import Annotated, get_args

# 1. 定義帶有欄位描述與數值範圍約束的型別
PositivePrice = Annotated[float, "單位: 新台幣 (TWD)", {"min": 0.0}]

# 2. 在執行期使用 get_args() 提取底層真實型別與所有元數據
args = get_args(PositivePrice)
real_type = args[0]   # 索引 0 -> 輸出: <class 'float'>
metadata  = args[1:]  # 切片 1: -> 輸出: ('單位: 新台幣 (TWD)', {'min': 0.0})

print(f"實質型別: {real_type.__name__}")
print(f"附加元數據數量: {len(metadata)}")
```

##### type 類別物件型別

- **使用時機**：在 Python 中，類別本身也是第一類物件。當函式參數要求傳入的是**「類別本體 (Class Object)」**，而不是該類別造出來的實例物件時使用。
- **語法**：
  - 現代語法 (3.9+)：`type[目標類別]`
  - 舊式語法 (3.8 前)：`typing.Type[目標類別]`
- **核心差異**：
  - `x: User`：`x` 是一個已經建立好的具體使用者物件實例。
  - `cls: type[User]`：`cls` 接收的是 `User` 類別本身（或是任何繼承自 `User` 的子類別）。

> **[生動比喻]**：  
> - `x: Car`：手裡握著「一台已經出廠組裝好的汽車實體」。  
> - `factory_cls: type[Car]`：手裡拿著「汽車工廠的設計圖紙與生產模具」，隨時可以在函式內部透過 `factory_cls()` 動態量產出新車！

```python
from typing import TypeVar

class Animal:
    pass

class Dog(Animal):
    def bark(self) -> str:
        return "汪汪！"

# 1. 基礎用法：接收類別本身，現場呼叫製造物件
def create_animal(cls: type[Animal]) -> Animal:
    # cls 接收的是類別本身，因此可以直接加上 () 實例化
    return cls()

my_dog = create_animal(Dog)  # 傳入 Dog 類別物件

# 2. 進階用法：搭配 TypeVar 實現靜態精準回傳推導
T = TypeVar("T")

def generic_factory(cls: type[T]) -> T:
    return cls()

# IDE 自動推導 dog_instance 的精確型別為 Dog，完全享有程式碼自動補全！
dog_instance = generic_factory(Dog)
print(dog_instance.bark())
```

# 5. 循環參照與靜態檢查隔離 (Circular Imports & Type Checking)

在規模化工程專案中，型別標註最常引發的兩大痛點是：**同檔案類別自引用 NameError** 與 **跨模組循環匯入 (Circular Import)**。Python 透過以下兩大法寶徹底解決。

##### from __future__ import annotations 延遲型別解析

- **使用時機**：
  - 在 **Python 3.7+** (PEP 563) 引入。當你在同一個檔案中定義類別，且該類別的方法需要標註**自身類別型別**時（如樹狀節點的 `parent: Node`，或鏈式調用回傳 `self` 的方法）。
  - 若未啟用此宣告，Python 在直譯類別定義內部時，該類別尚未建立完成，會直接拋出 `NameError: name 'Node' is not defined`。
  - 亦可用於在舊版 Python (3.7-3.9) 中提前享受 3.10+ 的管道符號語法 (`int | str`)，而不會在執行期引發語法剖析崩潰。
- **底層運作原理**：
  - 必須置於**檔案的最頂端（第一行可執行程式碼）**。
  - 它會告知直譯器：**在模組載入時，不要立即對型別標記進行表達式求值 (Evaluation)，而是直接將所有型別標記當作「純字串」儲存於 `__annotations__` 字典中**。

```python
from __future__ import annotations  # 必須放在檔案最頂部！

class TreeNode:
    def __init__(self, value: int, parent: TreeNode | None = None) -> None:
        self.value = value
        # 若無上方 future import，此處標註 TreeNode 會拋出 NameError！
        self.parent: TreeNode | None = parent
        self.children: list[TreeNode] = []

    def add_child(self, child: TreeNode) -> TreeNode:
        child.parent = self
        self.children.append(child)
        return self
```

##### TYPE_CHECKING 靜態檢查條件分支

- **使用時機**：
  - 在大型專案中，模組 A 為了寫型別註記需要引用模組 B 的類別，而模組 B 業務邏輯又需要匯入模組 A，導致 Python 拋出 `ImportError: cannot import name ... from partially initialized module ... (most likely due to a circular import)` 崩潰。
  - 或某個類別所屬的套件極為龐大（如 `pandas`、`torch`），只有在靜態型別分析時需要其型別，希望在程式啟動時避免耗時載入。
- **底層運作原理**：
  - `from typing import TYPE_CHECKING`。
  - `TYPE_CHECKING` 是一個特殊的常數。在常規執行期 (Runtime)，**它的值固定為 `False`**；但在 IDE（Pylance、Pyright）與靜態檢查器（mypy）分析程式碼時，**它的值被視為 `True`**！
  - 因此，包覆在 `if TYPE_CHECKING:` 內部的 `import` 陳述式，**在程式執行期完全不會被執行**，從物理層面徹底杜絕循環匯入！

> **[核心天條]：if TYPE_CHECKING 必須與 from __future__ import annotations 搭配使用！**  
> 在執行期，`if TYPE_CHECKING:` 區塊內的模組根本沒有被匯入。  
> 若檔案頂部漏寫 `from __future__ import annotations`，Python 在定義函式時會嘗試尋找該型別名稱，進而拋出 `NameError: name '...' is not defined` 崩潰！  
> 兩者必須結伴出現，不可分割。

```python
# 檔案：services/order_service.py
from __future__ import annotations  # 1. 必備：延遲型別解析防範 NameError
from typing import TYPE_CHECKING

# 2. 僅在靜態型別檢查期執行匯入，執行期完全跳過，徹底解耦循環依賴！
if TYPE_CHECKING:
    from models.user import User
    from models.product import Product

class OrderService:
    def create_order(self, user: User, items: list[Product]) -> int:
        # 執行期 user 與 Product 是透過鴨子型別或依賴注入傳入，無需在頂部直接 import
        print(f"為使用者 {user.name} 建立訂單")
        return 1001
```

# 6. 執行期型別內省與動態驗證 (Runtime Introspection)

在 **Python 3.8+** 的 `typing` 模組中，`get_origin()` 與 `get_args()` 是在**執行期 (Runtime) 拆解與剖析泛型型別 (Generic Types)** 的兩大核心神器。

##### 為什麼需要它們？解決什麼痛點？

當我們寫下 `list[str]`、`dict[str, int]` 或 `int | str` 時，它們在 Python 內部屬於特殊的泛型別物件（`GenericAlias` 或 `UnionType`）。
- **痛點 1**：無法直接用 `isinstance([1, 2], list[int])` 檢查，會直接拋出 `TypeError: Subscripted generics cannot be used with class and instance checks` 崩潰！
- **痛點 2**：直接比對 `tp == list` 會得到 `False`（因為 `list[int] != list`）。

`get_origin()` 與 `get_args()` 能將任何複雜的泛型別**如同洋蔥般逐層剝開**，這也是 **Pydantic、FastAPI、FastMCP** 等現代框架自動進行資料校驗與 Schema 生成的底層核心原理！

> **[生動比喻]**：  
> 面對一個快遞包裹 `list[str]`（裝滿字串的列表箱）：  
> - **`get_origin(tp)`**：拆開外箱，**告訴你最外層箱子是什麼容器規格**（`list`）。  
> - **`get_args(tp)`**：拿出內容物，**以元組形式告訴你箱子裡裝的物品型別規格是什麼**（`(str,)`）。

---

##### get_origin() 取得外層原始類別

- **使用時機**：在執行期需要判斷一個未知型別標註的「外層本體類別」時使用（例如判斷傳入的是否為列表、字典或聯合型別）。
- **語法**：`get_origin(tp: Any) -> Any`
- **回傳值**：
  - 若 `tp` 為泛型別，回傳其未帶參數的原始類別（如 `list[int]` -> `list`）。
  - 若 `tp` 為非泛型純型別（如 `int`、`str`），回傳 `None`。

---

##### get_args() 取得內部泛型參數元組

- **使用時機**：在執行期需要提取泛型別中「中括號內部所定義的型別引數」或「Annotated 元數據」時使用。
- **語法**：`get_args(tp: Any) -> tuple[Any, ...]`
- **回傳值**：
  - 包含內部所有參數之標準元組（例如 `list[int]` -> `(int,)`；若為純型別則回傳空元組 `()`）。

---

#### 泛型別執行期解構對照速查表

| 泛型型別註記 `tp` | `get_origin(tp)` (最外層原始類別) | `get_args(tp)` (內部參數元組) | 白話解構說明 |
| :--- | :--- | :--- | :--- |
| **`list[int]`** | `list` | `(int,)` | 外層是列表，內部元素為 `int` |
| **`dict[str, float]`** | `dict` | `(str, float)` | 外層是字典，Key 是 `str`，Value 是 `float` |
| **`tuple[str, int, bool]`** | `tuple` | `(str, int, bool)` | 外層是元組，內部各位置型別依序對應 |
| **`int \| str`** *(或 `Union[int, str]`)* | `types.UnionType` *(或 `Union`)* | `(int, str)` | 聯合型別，可為 `int` 或 `str` |
| **`str \| None`** *(或 `Optional[str]`)* | `types.UnionType` *(或 `Union`)* | `(str, <class 'NoneType'>)` | 等同於包含 NoneType 的聯合型別 |
| **`Literal["read", "write"]`** | `Literal` | `('read', 'write')` | 字面值限定，參數為允許的字面常數 |
| **`Annotated[float, "單位:元"]`** | `Annotated` | `(float, '單位:元')` | 第 0 項為實質型別，第 1 項起為元數據 |
| **`type[User]`** | `type` | `(User,)` | 外層是類別物件型別，內部為限定的目標類別 |
| **`int`** *(一般純型別)* | `None` | `()` | 非泛型別，無外層包裝與內部參數 |

```python
from typing import get_origin, get_args, Literal, Annotated

# 1. 列表與字典容器解析
t_list = list[int]
print(get_origin(t_list))  # 輸出: <class 'list'>
print(get_args(t_list))    # 輸出: (<class 'int'>,)

t_dict = dict[str, float]
print(get_origin(t_dict))  # 輸出: <class 'dict'>
print(get_args(t_dict))    # 輸出: (<class 'str'>, <class 'float'>)

# 2. 聯合型別 (Union / Optional) 解析
t_union = int | str
print(get_origin(t_union)) # 輸出: <class 'types.UnionType'>
print(get_args(t_union))   # 輸出: (<class 'int'>, <class 'str'>)

# 3. 字面值 (Literal) 與元數據 (Annotated) 解析
t_mode = Literal["r", "w", "a"]
print(get_origin(t_mode))  # 輸出: typing.Literal
print(get_args(t_mode))    # 輸出: ('r', 'w', 'a') (可直接用於檢查值是否合法)

t_meta = Annotated[int, "使用者 ID", {"gt": 0}]
print(get_origin(t_meta))  # 輸出: typing.Annotated
print(get_args(t_meta))    # 輸出: (<class 'int'>, '使用者 ID', {'gt': 0})
```

---

#### 實戰案例：自製執行期泛型型別驗證器

結合 `get_origin()` 與 `get_args()`，實作通用且防禦性極高的輕量級泛型驗證函式：

```python
from typing import get_origin, get_args, Literal, Union
import types

def validate_data(val: object, expected_type: type) -> bool:
    """在執行期精準驗證資料是否符合複雜的泛型型別註記"""
    origin = get_origin(expected_type)
    args = get_args(expected_type)
    
    # 情況 1: 一般純型別 (例如 int, str)
    if origin is None:
        return isinstance(val, expected_type)
    
    # 情況 2: Literal 字面值型別 (檢查值是否在允許的候選清單中)
    if origin is Literal:
        return val in args
    
    # 情況 3: Union / Optional 聯合型別 (只要符合其中一種型別即為合法)
    if origin is Union or origin is types.UnionType:
        return any(validate_data(val, arg) for arg in args)
    
    # 情況 4: list[...] 泛型列表 (檢查外層是 list，且內部每個元素均符合型別)
    if isinstance(origin, type) and issubclass(origin, list):
        if not isinstance(val, list):
            return False
        elem_type = args[0]
        return all(validate_data(item, elem_type) for item in val)
        
    return isinstance(val, origin)


# 實測驗證
print(validate_data([1, 2, 3], list[int]))               # 輸出: True
print(validate_data([1, "2", 3], list[int]))             # 輸出: False (內部混雜字串)
print(validate_data("admin", Literal["admin", "guest"])) # 輸出: True
print(validate_data("root", Literal["admin", "guest"]))  # 輸出: False
print(validate_data(None, str | None))                   # 輸出: True
```

# 7. 結構化介面協定 (Protocol & Structural Subtyping)

在 **Python 3.8+** (PEP 544) 引入 (`from typing import Protocol`)，用於實現**鴨子型別 (Duck Typing)** 的靜態型別檢查與介面契約。

- **核心目的**：無需明確繼承父類別，只要物件「擁有相同名稱與簽名的屬性或方法」，就被靜態型別檢查器視為符合該 Protocol 協定。
- **與 ABC (抽象基底類別) 的差異**：
  - **ABC (名義型別 Nominal Typing)**：必須顯式繼承 (`class GeminiProvider(BaseLLMProvider)`)。
  - **Protocol (結構型別 Structural Typing)**：無需繼承，實現跨模組徹底解耦。

> **[生動比喻]**：  
> - **ABC 抽象基底類別**：像「俱樂部會員驗證制」，進門必須出示實體會員證（明確繼承 `BaseLLMProvider`），守衛才放行。  
> - **Protocol 結構化協定**：像「特長檢驗自動通關門」，守衛不管你有沒有加入公會，只要你「走起來像鴨子、叫起來像鴨子（實作了 `.render()` 方法）」，系統就自動認定你是合格對象！

---

##### Protocol 結構化介面協定

- **使用時機**：定義一組抽象方法與屬性介面，讓第三方或呼叫端在無需繼承自身類別的情況下，享有完整的型別提示與靜態檢查。
- **語法**：繼承自 `typing.Protocol` 即可宣告為協定類別。

---

##### runtime_checkable 執行期協定檢查裝飾器

- **使用時機**：預設情況下，`Protocol` 僅供 IDE 與 Mypy 靜態分析。若要在程式執行期也能搭配 `isinstance(obj, MyProtocol)` 進行真實驗證，必須在協定上方套用此裝飾器。
- **語法**：`@runtime_checkable`

```python
from typing import Protocol, runtime_checkable

# 1. 定義 Protocol 介面協定 (無需繼承 ABC)
@runtime_checkable  # 賦予在執行期支援 isinstance() 檢查的能力
class Renderable(Protocol):
    """定義只要具備 render() 方法且回傳字串的物件，即符合 Renderable 協定"""
    def render(self) -> str:
        ...


# 2. 具體類別 A (完全沒有繼承 Renderable，但具備對應方法)
class MarkdownArticle:
    def render(self) -> str:
        return "# 這是 Markdown 文章內容"


# 3. 具體類別 B (同樣未繼承 Renderable)
class HTMLWidget:
    def render(self) -> str:
        return "<div>這是 HTML 元件</div>"


# 4. 函式使用 Protocol 進行型別標註
def display_component(component: Renderable) -> None:
    """傳入的物件不需要繼承特定父類別，只要有 render() 方法即可傳入"""
    print(f"渲染結果: {component.render()}")


# 測試調用：靜態檢查與執行期均完美通過
article = MarkdownArticle()
widget = HTMLWidget()

display_component(article)
display_component(widget)

# 搭配 @runtime_checkable 時可使用 isinstance 檢查
print(isinstance(article, Renderable))  # 輸出: True
```

---

#### ABC vs Protocol 深度規格對比

| 比較維度 | 抽象基底類別 (ABC) | 結構化協定 (Protocol) |
| :--- | :--- | :--- |
| **型別系統** | **名義型別 (Nominal Typing)**<br>必須顯式繼承父類別 | **結構型別 (Structural Typing)**<br>只要介面/方法簽名符合即可 |
| **代碼復用** | **支援**（可在父類別撰寫通用預設實作方法） | **不支援**（僅定義介面規格，不寫具體業務實作） |
| **強迫實作** | **執行期強迫**（漏寫 `@abstractmethod` 創建物件時直接報錯 `TypeError`） | **靜態檢查為主**（由 IDE/Mypy 提示，執行期預設不限制） |
| **解耦能力** | **較低**（第三方類別必須明確繼承你的 ABC） | **極高**（第三方類別完全無需感知你的 Protocol 存在） |

# 8. 執行期型別檢查函式

##### isinstance() 執行期型別檢查

- **使用時機**：在 Python 執行期，最安全、標準且推薦的變數型別校驗方式。
- **語法**：
  - 單一型別檢查：`isinstance(obj, class_or_tuple)`
  - 多型別聯合檢查 (3.10+)：`isinstance(obj, int | str)`
  - 多型別元組檢查 (通用)：`isinstance(obj, (int, str))`
- **參數說明**：
  - `obj`：待檢查的物件實例。
  - `class_or_tuple`：目標類別、類別元組，或使用 `|` 連結的聯合型別。
- **回傳值**：
  - `bool`：若物件為該類別或其任何子類別的實例，回傳 `True`。

> **[核心天條]：嚴禁使用 `type(obj) == Cls` 取代 `isinstance()`！**  
> `type(obj) == Cls` 屬於嚴格指標比對，會完全抹煞物件導向的**繼承多型 (Polymorphism)** 機制。  
> 若 `Dog` 繼承自 `Animal`，`type(dog) == Animal` 會得到 `False`，而 `isinstance(dog, Animal)` 才會正確回傳 `True`！

```python
class Animal:
    pass

class Dog(Animal):
    pass

my_dog = Dog()

# 1. 支援繼承鏈檢查 (推薦)
print(isinstance(my_dog, Dog))     # 輸出: True
print(isinstance(my_dog, Animal))  # 輸出: True (因為狗也是動物)

# 2. 嚴格比對 (容易踩雷，不推薦)
print(type(my_dog) == Animal)      # 輸出: False (無法辨識子類別繼承)

# 3. 現代多型別檢查語法 (Python 3.10+)
val = 42
```

# 實戰避坑與核心天條

## 1. 泛型別直接傳入 isinstance() 引發 TypeError

> **[核心天條]：嚴禁將帶有中括號參數的泛型別直接傳入 `isinstance()` 或 `issubclass()`！**

- **錯誤症狀**：
  程式執行時崩潰並拋出 `TypeError: Subscripted generics cannot be used with class and instance checks`。
- **背後原理**：
  `list[int]` 或 `dict[str, int]` 屬於 `GenericAlias` 泛型別名物件，Python 在執行期為了效能考量，不會在遍歷每個元素時逐一檢查型別。`isinstance()` 第二個引數僅能接收純類別或類別元組。

```python
# [錯誤寫法]：直接拿帶有泛型參數的型別進行檢查，引爆 TypeError 崩潰
# isinstance([1, 2, 3], list[int])

# [正確寫法 A]：檢查外層純類別
isinstance([1, 2, 3], list)

# [正確寫法 B]：透過 get_origin() 剝離外層類別後檢查
from typing import get_origin
target_type = list[int]
isinstance([1, 2, 3], get_origin(target_type) or target_type)
```

## 2. if TYPE_CHECKING 內部匯入漏寫延遲解析引發 NameError

> **[核心天條]：使用 `if TYPE_CHECKING:` 進行型別隔離時，檔案最頂端必須加上 `from __future__ import annotations`！**

- **錯誤症狀**：
  程式在靜態檢查時完全通過，但一啟動運行就立即崩潰，拋出 `NameError: name 'User' is not defined`。
- **背後原理**：
  在執行期，`TYPE_CHECKING` 為 `False`，因此其內部的 `from models import User` 完全未被執行，`User` 變數不存在於當前模組全域命名空間中。若未開啟延遲型別解析，函式在定義時會立刻求值 `user: User`，導致找不到變數而崩潰。

```python
# [錯誤寫法]：漏寫 future annotations，執行期引爆 NameError 崩潰
# from typing import TYPE_CHECKING
# if TYPE_CHECKING:
#     from models import User
# def handle(user: User): pass  # 崩潰！

# [正確寫法]：在第一行宣告延遲字串化解析
from __future__ import annotations
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from models import User

def handle(user: User) -> None:
    pass
```

## 3. tuple 標記單一元素漏加省略號導致長度鎖定

> **[核心天條]：標註不定長度同質元組時，必須寫為 `tuple[T, ...]`，切勿漏寫省略號！**

- **錯誤症狀**：
  傳入包含 3 個整數的元組 `(1, 2, 3)`，但靜態型別檢查器報警：`Expected tuple of length 1, got length 3`。
- **背後原理**：
  `tuple[int]` 代表**「長度嚴格為 1 且唯一元素為 int 的元組」**；若要表達「任意長度且元素皆為 int」，語法規定第二個引數必須為字面省略號 `...`。

```python
# [錯誤寫法]：誤以為 tuple[int] 是任意長度 int 元組 (實際上長度被鎖定為 1)
def process_data(data: tuple[int]) -> None:
    pass
# process_data((1, 2, 3)) # mypy 報錯！

# [正確寫法]：加上省略號 ... 表達不定長度
def process_data_fixed(data: tuple[int, ...]) -> None:
    pass
process_data_fixed((1, 2, 3)) # 通過
```

## 4. 可選參數預設值 None 漏寫 Optional 或 | None

> **[核心天條]：當參數預設值為 `None` 時，型別標記必須顯式宣告為 `T | None`！**

- **錯誤症狀**：
  靜態型別檢查器拋出 `Incompatible default for argument "name" (default has type "None", argument has type "str")`。
- **背後原理**：
  在早期 Python (PEP 484) 中曾有「隱式可選 (Implicit Optional)」行為（若預設值為 `None`，直譯器自動將型別推導為 `Optional[T]`）。但自 PEP 484 修正與現代 Python 起，此隱式行為已被全面廢棄，必須顯式標明。

```python
# [錯誤寫法]：標註為 str 卻賦予 None 預設值，靜態檢查器報錯
# def query(name: str = None): pass

# [正確寫法]：顯式宣告聯合型別為 str | None
def query(name: str | None = None) -> None:
    pass
```
